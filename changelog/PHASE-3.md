## 2026-09-06 · Phase 3 补丁四：大模型增强层（NPC 交谈 / AI 日常小事件 / API 接入）

**作者需求**：调用大模型辅助 NPC 对话、日常文本、简单事件表现、随机事件、本地快速生成；支持 API 接入；本机接入本地模型 `D:\AI\models\Ornith-1.5-9B-Heretic-Q4_K_M`（64K 上下文）；**保留原逻辑，没有大模型也能推进剧情/事件**。

**架构原则**：LLM 只产文本与"情绪分类"，**所有数值效果走白名单映射**（warm/neutral/distant、good/tough/neutral → 固定微数值），模型给不了数字，不破坏平衡与既有测试；解析全程容错；AI 关闭/失败时静默回退原内容，**游戏主循环零改动**。

**新增内容**：

1. **Core 层（纯 C#，可测试）**：`Core/Llm.cs`——LlmConfig（默认指向本机 llama-server）、LlmPrompt（世界观摘要＋NPC 档案/关系/记忆/当前状态 → 严格 JSON 指令）、LlmJson（容错解析：容忍 ``` 包裹与前后杂文；内置 MiniJson 解析器保持 Core 无 UnityEngine 依赖；字段缺失/非法 mood 全部归一化）、LlmGameplay（交谈/小事件 → 白名单效果＋事件构建）。`Core/ContentNpcTalk.cs`——9 名 NPC 各 4 条内置台词（口吻贴合人设），作为无 AI 回退。
2. **Ui 层**：`Ui/LlmClient.cs`（OpenAI 兼容 Chat Completions，UnityWebRequest；思维链模型正文为空时兜底读 reasoning_content）、`Ui/LlamaServer.cs`（自动拉起 llama-server；**显存不足时自动降级阶梯**：全量 GPU→半量→少量→纯 CPU，进程早退立即换档；应用退出回收子进程）。
3. **玩法一 · NPC 交谈**：人物页签改为 NPC 卡片（姓名/职务/关系数值/最近记忆＋"交谈"按钮）→ 交谈弹层（AI 生成开场、后续对话、两个玩家回应选项及其反应；选择后应用白名单效果并写记忆，可"再聊一句"）。无 AI 时用内置台词池，体验完整。
4. **玩法二 · AI 日常小事件**：普通工作日（无脚本事件）有 45% 概率异步生成一个"小插曲"（基于当日状态与当月城市背景），生成完毕后替换日常伪事件进入主循环，选项效果走白名单；每日最多一次（`GameState.lastAiMicro`，向后兼容字段，saveVersion 仍为 3）；快进不触发。
5. **设置页 · AI 接入区**：总开关、本地 llama-server / 外部 OpenAI 兼容 API 两种模式、服务地址/密钥/模型名/llama-server 路径/模型路径五项输入、**测试连接**（含本地服务自动拉起）。配置存 PlayerPrefs（本机专属，不入存档），默认启用本地模式。
6. **工程**：manifest.json 启用 `com.unity.modules.unitywebrequest(+audio)/audio` 内置模块；Ui asmdef 增补对应模块引用。

**本机实测（RTX 3060 Laptop 6GB）**：模型 5.63GB 超出可用显存，降级阶梯自动落到"少量 GPU＋16K 上下文"档；发现该模型默认输出思维链（正文为空），启动参数加 `--jinja --reasoning-budget 0` 关闭后，真实生成 247 token / 约 21 秒，产出完全符合游戏 JSON 协议、口吻贴合周衡之人设（"数字不能打架""笔下护人"）。速度约 13 t/s（含提示词处理）。

## 2026-09-06 · 补丁四·附二：MoE 横评（Gemma-4-26B-A4B）——prefill 瓶颈实锤

**配置**：gemma-4-26B-A4B-it-UD-IQ4_XS（13.6GB 单文件），i9-12900H＋16GB 内存＋RTX 3060 Laptop 6GB；`-ngl 99 --n-cpu-moe 99`（注意力/共享核＋KV 上 GPU 占 5.0GB，专家全留 CPU——显存仅剩约 150MB，无再上收空间）。

**结论**：MoE 的 A4B 生成优势在小显存机器上被 CPU 侧专家 prefill 吃掉，且 Gemma 家族格式纪律偏弱；**6GB 显存不是它的正确打开方式**（专家全上 GPU 需要 ≥16GB 显存，届时 prefill 可恢复数百 t/s）。现役默认维持 Heretic-Q4_K_M。
